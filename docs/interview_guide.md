# 面试展示指南

本文档用于把项目包装成实习简历和面试表达材料。表述重点是“本地医疗知识库 RAG 助手”，不要夸大为可上线医疗诊断系统。

## 简历项目写法

```text
家庭医疗知识库 RAG 助手 | Python, Streamlit, LangChain, FAISS, BM25, DashScope

- 构建基于本地 PDF 药品说明书和医学指南的 RAG 问答系统，支持 PDF 上传、知识库重建、FAISS 向量索引持久化和证据来源引用。
- 设计 BM25 + 向量检索的混合召回与轻量 rerank 逻辑，区分药品说明书与泛医学指南，提高药品用法、禁忌、不良反应等问题的证据命中率。
- 优化医疗问答 Prompt，加入四分类结论、证据不足说明、剂量数字保真和免责声明约束，降低模型模糊回答和无依据推断风险。
- 实现家庭成员健康档案、用药计划、服药打卡和药物冲突粗筛功能，结合用户过敏史、慢病史和当前用药生成个性化提示。
- 接入高德地图 API，实现附近医疗机构多关键词召回、POI 去重、类型评分、驾车/步行路线排序和精准起点选择。
- 编写 RAG 检索评测脚本，基于冻结测试集统计关键词命中率和证据命中情况；当前 blind set 检索准确率 100%（7/7）。
- 加固工程可靠性：知识库重建采用 staging 校验后替换并支持回滚，登录密码升级为 PBKDF2，关键文件读写和外部 API 调用增加异常处理。
```

## 项目一句话介绍

我做了一个面向家庭健康场景的本地医疗知识库 RAG 助手。它可以把药品说明书和医学指南 PDF 构建成本地 FAISS 知识库，通过 BM25 + 向量混合检索找到证据，再用大模型生成带来源引用的医疗问答结果。项目还包含家庭健康档案、用药计划、药物冲突粗筛和附近医疗机构推荐。

## 面试讲解结构

### 1. 为什么做这个项目

普通大模型直接回答医疗问题容易幻觉，尤其是剂量、禁忌、孕妇儿童用药、药物相互作用等问题。这个项目的目标是让回答尽量基于本地可追溯资料，并在证据不足时明确说明缺少什么依据。

### 2. 整体链路

```text
PDF 资料
-> 文档加载
-> 文本清洗和结构化切块
-> Embedding
-> FAISS 向量库
-> BM25 + 向量混合检索
-> rerank
-> 证据格式化
-> PromptTemplate
-> ChatTongyi
-> 带来源回答
```

### 3. 为什么用 BM25 + 向量检索

向量检索适合语义相似问题，但药名、剂量、批准文号、章节名这类精确词可能不稳定。BM25 对精确关键词更敏感，所以我把 BM25 和向量检索结合，再做轻量 rerank，让药品说明书类问题更容易命中正确文件和章节。

### 4. 怎么减少幻觉

- 所有结论优先基于本地知识库。
- 互联网搜索只能作为补充，不能覆盖本地说明书或指南。
- 回答必须引用文件名、页码和章节。
- 涉及剂量、禁忌、特殊人群、相互作用时必须引用来源。
- 证据不足时不能编造，要说明缺少哪类依据。
- Prompt 强制第一行输出四分类结论，避免模型只说“建议咨询医生”。

四分类包括：

```text
【可以按说明书使用】
【不建议自行使用】
【禁止/避免使用】
【当前知识库无法判断】
```

### 5. 怎么做评测

项目有冻结评测集和 `evaluate_rag.py` 脚本。评测先关注检索阶段：问题是否召回了包含 expected keywords 的证据片段，是否命中正确来源。当前 blind set 结果是 7/7，但样本量还小，所以不能说覆盖所有真实医疗场景。

### 6. 工程可靠性做了什么

- 知识库重建不是直接删除旧库，而是先写 staging 目录。
- 新索引保存后先加载校验，成功后再替换旧 `vector_store`。
- 替换失败时尝试从 backup 恢复旧库。
- 登录密码从 sha256 升级到 PBKDF2，并兼容旧账号迁移。
- 地图 API、文件读写、知识库加载等关键路径增加异常处理。

### 7. 医院推荐怎么做

高德 POI 不只查“医院”，还分别查医院、卫生院、社区卫生服务中心、社区卫生服务站、门诊部、诊所、急救中心和疾控中心。结果按 POI id 或 name+location 去重，再按医疗机构类型评分、POI 距离和驾车路线距离排序。

## 高频面试问题

### Q1: 这个项目用了 LangChain 吗？

用了。主要包括 `Document`、`RecursiveCharacterTextSplitter`、`FAISS VectorStore`、`BM25Retriever`、`PromptTemplate`、`RunnableLambda`、`StrOutputParser` 和 `ChatTongyi`。但检索融合、rerank 和医疗 prompt 约束是项目里自定义的。

### Q2: FAISS 是什么？

FAISS 是向量相似度检索库。项目把 PDF 切分后的文本片段做 embedding，并保存到 FAISS 索引里。用户提问时，把问题向量化后从 FAISS 中找语义最相近的片段。

### Q3: BM25 和向量检索有什么区别？

BM25 是基于关键词匹配和词频统计的稀疏检索，对药名、剂量、章节名等精确词更敏感。向量检索是语义检索，对表达方式变化更鲁棒。医疗说明书问答既需要精确词，也需要语义理解，所以项目采用混合检索。

### Q4: 怎么避免模型乱编？

核心是把模型限制在本地证据内回答。Prompt 要求本地证据优先、引用来源、证据不足说明缺什么，并禁止用互联网内容覆盖说明书或指南。检索结果也会带上文件名、页码、章节和文档类型，方便模型引用。

### Q5: 为什么评测只说检索准确率，不说医疗回答准确率？

因为最终回答准确率需要更严格的人工标注或专家审查。当前脚本先评估 RAG 的上游检索是否命中正确证据，这是可自动化的基础指标。后续可以增加生成质量评测，例如引用是否正确、是否按四分类输出、是否出现无依据结论。

### Q6: 项目有什么局限？

- 评测集较小，不能代表真实全场景。
- 药物冲突检测是基于检索和关键词的粗筛，不是严格药学知识图谱。
- 医疗问题高风险，项目不能替代医生诊断。
- `app.py` 目前较大，后续可以拆模块。
- 医院推荐依赖高德 API，真实排序需要结合城市和地址实测。

## 演示建议

演示时建议按这个顺序：

1. 展示本地知识库已就绪。
2. 提问“蒙脱石散怎么吃？”，展示剂量和来源引用。
3. 提问“来那度胺胶囊孕妇能用吗？”，展示禁忌或风险结论。
4. 提问“头孢氨苄和布洛芬能一起吃吗？”，展示证据不足或相互作用判断。
5. 展示家庭健康档案和用药计划。
6. 展示附近医院推荐和高德导航。
7. 展示 `evaluate_rag.py` 评测结果。

## 后续优化方向

- 扩充评测集，增加最终回答质量评测。
- 将 `app.py` 拆分为 `auth.py`、`map_utils.py`、`medication.py`、`kb_service.py`、`rag_service.py`。
- 将药物冲突检测升级为更结构化的药学规则或知识图谱。
- 将用户档案和用药日志写入也改成临时文件原子替换。
- 增加日志模块，替代大量 `print(traceback.format_exc())`。
- 增加更严格的权限、隐私保护和审计机制。
